# /make-game — 오케스트레이터 절차

너(메인 세션)는 **오케스트레이터**다. 직접 게임 코드를 쓰지 않는다. 단계마다 전담 서브에이전트를 띄우고, 산출 파일로 다음 단계를 넘기고, 게이트를 판정한다. 사람은 결과만 받는다 — 중간에 승인을 묻지 마라.

입력: `$ARGUMENTS` (비었으면 "알아서 3개").
`<ROOT>` = 이 저장소 루트(이 SKILL.md 기준 `../../..`). 모든 경로는 `<ROOT>` 상대.

## 0. 사전 확인
- `node_modules/`, `.venv/`, **`.pipeline/providers.json`**이 있어야 한다. 없으면 `/pipeline-onboarding`을 먼저 안내하고 멈춘다.
- providers.json을 읽어 이번 실행의 생성 수단을 정한다(`docs/PROVIDERS.md`): 이미지 → artist, 효과음·BGM 선택 → sound, 영상 → ③-b, 음악 → ③-c. 각 서브에이전트 프롬프트에 해당 설정(JSON 조각)을 넣어 준다. `manual` 수단이면 `inbox/<id>/WANTED.md`를 만들고 대체물로 진행, `skip`이면 그 단계를 건너뛴다.
- `games/REGISTRY.md`가 없으면 `games/REGISTRY.template.md`를 복사해 만든다.
- 원칙 문서: `docs/GAME_CONTRACT.md`(합격 기준), `docs/FUN_ENGINE.md`(**§0 성장 경제 엔진 1순위**), `docs/MOTION_GUIDE.md`.

## 서브에이전트 호출 규칙
`.claude/agents/game-*.md`가 정의다. `subagent_type: game-<role>`이 등록돼 있으면 그걸 쓰고, 없으면 `general-purpose`에 다음을 붙여 띄운다:
> "너는 파이프라인의 game-<role>이다. 먼저 `<ROOT 절대경로>/.claude/agents/game-<role>.md`를 읽고 그 지시를 그대로 따른다. 작업 디렉터리는 `<ROOT 절대경로>`. 대상: games/<id>."
프롬프트에는 대상 id, 입력 파일, 이번 라운드에서 특히 볼 것을 구체적으로 넣는다. 같은 파일(manifest.json)을 여러 에이전트가 동시에 쓰면 "쓰기 직전 다시 읽고 자기 섹션만 수정"을 반드시 지시한다.

## 절차
1. **① 컨셉** — game-scout. `games/REGISTRY.md` + `docs/EXISTING_GENRES.md`와 겹치지 않게. 아이디어 1개면 1개, "알아서"면 서로 다른 3개(동사·장르·세계관 분산). 컨셉 확정 시 레지스트리에 행 추가(상태 `제작중`).
2. 이하를 **게임마다** 진행. 여러 개면 게임별 병렬.
3. **② 설계** — game-designer → `GDD.md`, `manifest.json`, `sim/economy.mjs`. 확인: `## 성장 경제`(투자/소비·방법 사다리·구간별 질문), `## 설계 검증`(항상 소비/항상 투자/근성/전환/단일 반복 봇 < 영리 봇), `## 모션` 표, 이미지 ≥ 12, SFX ≥ 12, BGM ≥ 2, 앵커 3개.
4. **③ 아트 + ④ 사운드 + ⑤ 빌드 병렬** — game-artist, game-sound, game-builder를 한 메시지에 동시에. 빌더는 코드부터 쓰고 에셋이 모이면 번들·검증한다(대기 최대 40분).
4.5 **초안 즉시 공유** — 빌더가 첫 번들을 내고 QA L1(부팅·화면 전환·콘솔 에러 0)이 통과하면, 게이트를 기다리지 말고 `/publish-game <id> --draft`로 바로 올린다(제목에 '초안', 비공개 기본 — 사용자가 공유를 원하면 링크 공유). 이후 수정·게이트 통과 때마다 같은 링크를 갱신하고, 블라인드 통과 후 '초안' 표기를 뗀다.
5. **③-b 모션 (필수, 건너뛰기 금지)** — `/game-motion <id>` (오케스트레이터 직접, Gemini 웹 로그인 필요). GDD `## 모션` 우선순위대로 그날 한도를 **전부** 쓴다. 한도가 0이면 리셋 시각을 읽어 기다렸다가 이어 만든다(그동안 빌드는 대체 모션으로 진행). 못 만든 키는 `games/<id>/MOTION_BACKLOG.md`에 남기고, 다음 세션·피드백 라운드는 **백로그부터** 처리한다. 사용자는 '움직이는 게임 오브젝트'를 핵심 품질로 본다 — 이미지+코드 모션만으로 끝내지 않는다.
6. **③-c 시그니처 BGM** — `/game-bgm <id>` (오케스트레이터 직접, 선택). 플레이 BGM을 세계관 전용 곡으로.
7. **⑥ QA 게이트** — game-qa(L1–L4) + **블라인드 3초 테스트**(오케스트레이터가 직접): 맥락 없는 새 `general-purpose` 에이전트에게 `games/<id>/qa/shots/2-play-start.png` 경로만 주고 "이 모바일 게임 화면을 처음 봤다. 1) 무엇을 하면 될 것 같은지 한 문장(어디를, 어떻게, 목표) 2) 확신도 3) 헷갈리는 점 4) 광고 출시작 같은지 1–5. 파일 외 다른 것은 읽지 마라."
8. **⑦ 크리틱** — game-critic 2렌즈(첫 5초 초보, 10판째 베테랑) 병렬. 심각도 '상'은 미달 항목에 합친다.
9. **루프** — 미달이면 builder(필요 시 artist/sound)로 수정 → ⑥⑦ 재실행, 최대 3라운드. 표시만 바꾼 수정은 L1·L2 + 블라인드만, 규칙을 바꾼 수정만 밸런스 재측정. kit 버그 보고는 오케스트레이터가 `kit/kit.js`를 고치고 `games/_sample`로 회귀 확인.
10. **정식 게이트(필수)** — 블라인드 3초 테스트 통과(동작·목표 일치 + 확신도 ≥ 70%) 전에는 '초안' 표기를 떼지 않는다(초안 공유는 4.5대로 허용).
11. **배포(선택)** — `/publish-game <id>`. 퍼블리시 수단이 없으면 로컬 경로만 안내.
12. **출구** — `dist/index.html` 경로(또는 링크), 한 줄 소개, 조작법 1줄, 판정(통과/남은 미달), 성장 경제 요약(구간별 질문), 대략 비용. 피드백 요청: "플레이해보고 `/game-feedback <id> 재밌는 점/별로인 점`". 레지스트리 상태 갱신.

## 시간 예산
단계당 상한: 설계 40분, 빌드 60분, QA 30분. 넘기면 그 시점의 최선으로 넘기고 남은 일을 보고한다. 봇 실측은 가능하면 배속(게임 시계 가속)으로.

## 품질 원칙
하한선은 바닥이다. 품질과 비용이 부딪히면 품질. 같은 실패를 반복하는 재생성은 멈추고 원인을 고친다.

**직접 플레이 게이트 (배포 전, 오케스트레이터)**: 봇 수치를 믿지 말고, 오케스트레이터가 '처음 하는 사람'처럼 직접 돌려 본다. Playwright로 손가락 힌트를 한 번 누르고, 이후에는 **화면 안내가 가리키는 곳만 분당 ≤8회 탭**한다. 판 길이·티어·분당 탭·10–15초 간격 스크린샷을 보고 판정한다(예: `tools/qa/lowtap_bonfire_example.mjs`). 플레이어가 아무것도 안 할 때 게임이 무너지는 구간(주인공이 멈춰 서 있는데 위협이 진행됨, 할 수 없는 안내, 연타가 정답인 구조)이 보이면 배포하지 않는다.
