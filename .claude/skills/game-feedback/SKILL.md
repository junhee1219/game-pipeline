# /game-feedback — 오케스트레이터 절차

입력: `$ARGUMENTS` = `<id> <피드백>`. id가 없으면 가장 최근 수정된 `games/*`를 대상으로 하고 그렇게 했다고 알린다.

1. **기록** — `games/<id>/game-feedback-log.md` 맨 위에 날짜·현재 버전(v1, v2…)·피드백 원문을 추가.
2. **보호 목록 갱신** — 피드백에서 "재밌다/좋다"로 언급된 요소를 GDD.md의 `🔒 건드리지 말 것`에 한 줄씩 추가(무엇이, 왜 — 사람 말 인용).
3. **진단** — game-critic 3렌즈(첫 5초 초보 / 10판째 베테랑 / 방금 끈 이탈자)를 병렬로. 피드백 원문을 최우선 근거로 준다.
4. **변경안** — 오케스트레이터가 발견을 순위화해 변경안(최대 5개, 각 1–3줄)을 만든다. 🔒 항목을 훼손하는 변경은 버린다. 사람 승인은 받지 않는다(사람은 피드백만 준다).
5. **버전 보존** — 현재 `dist/index.html`을 `dist/v<N>/index.html`로 복사.
6. **적용** — 필요한 단계만 다시: GDD 수정이 필요하면 game-designer(변경분만), 에셋이면 game-artist/game-sound(`--only`), 코드는 game-builder.
7. **게이트** — make-game 절차 7–10과 동일(QA + 블라인드 + 크리틱, 최대 3라운드, 블라인드 통과 전 배포 금지). 피드백이 판단의 얕음·꼼수·난이도에 관한 것이면 `docs/FUN_ENGINE.md §0`(성장 경제) 기준으로 설계부터 다시 본다.
8. **배포(선택)** — 이전에 배포된 게임이면 `/publish-game <id>`로 같은 링크를 갱신.
9. **출구** — 새 `dist/index.html` 경로 + "이번에 바뀐 것과 그 이유" 3줄(각 줄이 어떤 피드백에서 왔는지) + 보호 목록에 올린 것. feedback-log.md에 변경 요약을 덧붙인다(게임 폴더는 로컬 전용, git 미추적). 피드백에서 **모든 게임에 해당하는 교훈**이 나오면 `docs/`·`.claude/agents/`에 원칙으로 올리고 그것만 커밋한다.

**모션 백로그**: `games/<id>/MOTION_BACKLOG.md`가 있으면 이 라운드에서 `/game-motion <id>`으로 그날 한도만큼 먼저 처리한다.

**직접 플레이 게이트 (배포 전, 오케스트레이터)**: 봇 수치를 믿지 말고, 오케스트레이터가 '처음 하는 사람'처럼 직접 돌려 본다. Playwright로 손가락 힌트를 한 번 누르고, 이후에는 **화면 안내가 가리키는 곳만 분당 ≤8회 탭**한다. 판 길이·티어·분당 탭·10–15초 간격 스크린샷을 보고 판정한다(예: `tools/qa/lowtap_bonfire_example.mjs`). 플레이어가 아무것도 안 할 때 게임이 무너지는 구간(주인공이 멈춰 서 있는데 위협이 진행됨, 할 수 없는 안내, 연타가 정답인 구조)이 보이면 배포하지 않는다.
