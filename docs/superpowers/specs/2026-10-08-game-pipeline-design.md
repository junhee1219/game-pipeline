# 게임 찍어내기 파이프라인 — 설계 스펙

> 2026-10-08 · 작성: Claude(브레인스토밍 세션)
> 입력 자산: 이전 게임 포털 프로젝트의 원칙 문서(CORE_FUN_ENGINE · GAME_PRINCIPLES · 에이전트 3종), 게임 심리학 연구 문헌.

## 1. 목적과 범위

Claude Code 세션이 **아이디어 한 줄(또는 "알아서 3개")을 받아 프로덕션급 HTML 게임을 무인으로 찍어내는 파이프라인**.
사람은 결과를 플레이하고 "뭐가 재밌다 / 뭐가 별로다" 피드백만 준다. 피드백은 파이프라인의 두 번째 입구다.

- 용도: 개인 프로젝트.
- 품질 기준: 비주얼·연출·사운드·손맛 모두 **앵그리버드 / 로얄매치 / 유튜브 광고 캐주얼 게임** 수준.
- 범위 밖: 외부 포털 연동, 앱 통합, 보상 실연동(규칙만 설계에 반영), 서버.

## 2. 게임 계약 (모든 산출물의 합격 기준 — `docs/GAME_CONTRACT.md`의 원본)

> **하한선은 바닥이지 목표가 아니다.** 아래 수치는 "이 밑이면 출구로 못 나간다"는 기준일 뿐이다. 모든 단계는 기준을 간신히 넘기는 게 아니라 **가능한 한 최고 품질**을 겨냥한다. 연출은 5종이 아니라 게임이 허락하는 만큼 풍부하게, 아트는 low로 충분하지 않은 에셋은 퀄리티를 올리고, QA L4는 4점 통과에 멈추지 않고 5점을 노린다. 비용·시간과 품질이 부딪히면 품질 쪽으로 기운다.

### 2.1 결과물은 HTML
- 최종 산출물 = **단일 `index.html`**. 이미지·사운드·엔진을 인라인(base64/inline script). `file://` 더블클릭으로 실행. 외부 네트워크 요청 0.
- 개발 중엔 `assets/` 폴더로 작업, 번들 단계에서 합친다. 목표 크기 ≤ 10MB.

### 2.2 복잡하지 않고 쉽게
- **엄지 하나, 동사 하나**(탭 | 드래그 | 스와이프 중 하나).
- **설명 텍스트 없이 3초 안에** 할 일이 자명. 튜토리얼은 손가락 힌트 애니메이션 1개 수준.
- 한 판 1–3분. 기본 시간제한 없음.
- 깊이는 규칙 추가가 아니라 같은 동작에서 창발. 변형기(3택1)는 첫 문턱 이후에만, 게임이 필요할 때만.

### 2.3 완성도
- 화면: 타이틀 → 플레이 → 일시정지 → 결과(다시하기·최고기록). 진행 자동 저장·이어하기, 음소거 상태 저장.
- 아트: 레퍼런스 주입으로 스타일 통일된 스프라이트. **도형·이모지·플레이스홀더 0.**
- 연출(juice) **최소 5종**(파티클, 셰이크, 스쿼시&스트레치, 플로팅 숫자, 콤보 팝, 등장 바운스, 임팩트 링 등). 문턱 돌파·신기록 전용 피크 연출.
- 사운드: BGM ≥ 2곡(로비·플레이), SFX ≥ 10종. 입력 반응은 같은 프레임.
- 모바일 세로(390×844) 60fps, 콘솔 에러 0.

### 2.4 재미 (FUN_ENGINE)
- **이름 붙은 문턱 사다리** — 숫자를 가려도 서열이 보이는 티어(예: 동전 → 지폐 → 금괴). 다음 칸 실루엣 노출.
- 긴장은 **접전과 출렁이는 리듬**으로. 연출은 *성공*에 붙인다.
- **정직한 니어미스만.** 결과 조작·가짜 니어미스·속이는 난이도 조절 금지.
- 실패 원인이 화면에 보인다("내가 더 잘할 수 있었다").
- 신기록은 붙잡는 장치가 아니라 기분 좋게 끝내는 순간.
- 보상(포인트) 연동 시 규칙(설계에만 반영): 판당 예고 포인트 금지, 하루 상한, 포인트 뽑기 금지, 스트릭은 복구 가능, 니어미스 직후 이어하기 판매 금지.

## 3. 아키텍처

오케스트레이션은 **Claude Code 스킬 + 서브에이전트**(접근 A). 단계 산출물을 **파일 계약**으로 고정해, 나중에 Workflow 스크립트(병렬화)나 헤드리스 `claude -p`(무인 운영)로 감쌀 수 있게 한다.

### 3.1 레포 구조
```
mini-game/
├── CLAUDE.md                 파이프라인 헌법 요약 + 스킬 라우팅
├── .env                      OPENAI_API_KEY (gitignore, 커밋 금지)
├── docs/GAME_CONTRACT.md     §2
├── docs/FUN_ENGINE.md        CORE_FUN_ENGINE + 논문 리뷰 요약
├── .claude/skills/make-game/ 입구
├── .claude/skills/game-feedback/  재진입
├── .claude/agents/           scout · designer · artist · sound · builder · qa · critic
├── tools/                    gen_image.py · sound_lib/ · bundle.mjs · qa/
├── kit/                      공통 런타임 (§3.3)
└── games/<id>/               concept.md · GDD.md · manifest.json · assets/ · src/ · dist/ · qa-report.md · feedback-log.md
```

### 3.2 단계 (각 단계는 앞 단계 파일만 읽고 자기 파일만 쓴다)
| # | 에이전트 | 입력 → 출력 | 책임 |
|---|---|---|---|
| ① | scout | 아이디어/없음 → `concept.md` | 즉시성(3초 동작), 코어 결정, 문턱 사다리, 한 줄 세계관. "알아서"면 서로 안 겹치는 3개 |
| ② | designer | → `GDD.md` + `manifest.json` | 코어 루프·문턱 수치·연출 목록·화면 목록. 모든 에셋을 프롬프트/태그 단위로 나열 |
| ③ | artist | manifest → `assets/img/` | 스타일 앵커 3장 → 비전으로 최선 선택 → 레퍼런스로 나머지 생성 → 투명 배경 → 비전 일관성 검수 |
| ④ | sound | manifest → `assets/audio/` | 로컬 CC0 사운드 라이브러리에서 태그로 선택(③과 병렬). 길이·음량·루프 확인 |
| ⑤ | builder | GDD + assets + kit → `src/` → `dist/index.html` | 게임 로직만 작성. 화면·연출·사운드·저장은 kit 사용 |
| ⑥ | qa | dist → `qa-report.md` | §4 게이트. 미달 시 ⑤로 되돌림, 최대 3회 |
| ⑦ | critic | 봇 로그 + GDD | 구조적 재미 결함(지배 전략, 벽, 결정 공백). 심각하면 ⑤로 |

- "알아서 3개": 컨셉 3개 → **3개 모두 끝까지 빌드**(서브에이전트 병렬).
- 예상 비용: 게임당 이미지 $1–5(low quality 기준). 사운드 0(CC0 로컬 라이브러리).

### 3.3 kit — 공통 런타임
- 기반: **Phaser 3**(씬·트윈·파티클·오디오·입력·스케일링). min 빌드를 번들에 인라인.
- kit가 얹는 것: 연출 프리셋(`juice.shake/pop/squash/floatText/burst/ring/comboPop`), 표준 화면(타이틀·일시정지·결과), 저장/이어하기, 오디오 매니저(BGM 크로스페이드·음소거 저장·SFX 피치 변주), **계측 이벤트**(juice/sfx/scene 발동 기록), **`window.__test` 인터페이스**(상태 조회·가능한 수·한 수 실행·시드 고정).
- 게임 코드는 kit API로 화면 흐름을 얻고, 코어 로직과 그 게임 고유 연출만 쓴다.

### 3.4 에셋 도구
- **이미지** `tools/gen_image.py`: OpenAI `images.edit`/`generations`, 모델·퀄리티는 설정값(기본 `gpt-image-2.5-sunburst`, `low`). 히어로 에셋만 `--quality` 상향 가능. 레퍼런스 주입(스타일 앵커), 투명 배경. 키는 `.env`.
- **사운드** `tools/sound_lib/`: Kenney 등 CC0 팩을 한 번 내려받아 `index.json`(파일·태그·길이)로 색인. sound 에이전트는 태그로 고른다. 프로덕션 전환 시 ElevenLabs/Lyria 생성으로 교체(인터페이스 동일).

## 4. QA 게이트 (프로덕션급 하한선)

아래 층부터 순서대로. 미달 시 리포트와 함께 builder로 되돌림(최대 3회). 3회 안에 못 넘으면 **미달 항목을 `qa-report.md` 맨 위에 명시하고** 출구로 넘긴다(은폐 금지).

- **L1 기술(Playwright)**: `file://` 실행, 외부 요청 0, 콘솔 에러 0, 390×844 + CPU 4배 스로틀에서 평균 ≥ 55fps, 새로고침 후 이어하기, 음소거 유지, 모든 화면 도달, 크기 ≤ 10MB.
- **L2 계약 이행(kit 계측)**: 봇 한 판 동안 juice ≥ 5종, SFX ≥ 10종, BGM 재생, 문턱/신기록 피크 연출 발동. manifest 에셋 전부 로드·사용.
- **L3 플레이(봇 시뮬레이션)**: 랜덤 봇 — 크래시 없이 반드시 종료. 탐욕 봇 — 첫 문턱 60초 내 도달 ≥ 90%, 최고 티어 도달 가능하되 드묾. 전략 간 성과 격차로 지배 전략 판정. 판 길이 중앙값 1–3분. 코드 검사로 결과 조작·가짜 니어미스 없음.
- **L4 비전(Claude 멀티모달)**: 타이틀·플레이·콤보·결과 스크린샷을 루브릭(스타일 일관성·가독성·엄지 영역 UI·"광고에 나올 만한가") 1–5점, 전 항목 ≥ 4. **블라인드 3초 테스트**: 맥락 없는 새 서브에이전트에게 첫 화면만 보여주고 "뭘 하면 될까?" — 의도한 동작과 다르면 실패.
- QA는 "재밌냐"를 판정하지 않는다. 재미의 *조건*까지만 보장하고, 판정은 사람이 한다.

## 5. 피드백 루프
```
/game-feedback <id> "보스 터질 때 손맛 최고. 근데 3판째부터 지루함"
 → feedback-log.md에 버전과 함께 누적
 → critic 3렌즈(첫 5초 초보 / 10판째 베테랑 / 방금 끈 이탈자)가 피드백 + 봇 로그로 진단
 → 문제 순위 + 변경안 → builder → QA 게이트 → dist/v2
 → "이번에 바뀐 것과 그 이유" 3줄 요약
```
- 변경안은 승인 없이 자동 적용(사람은 피드백만).
- "재밌다" 피드백은 GDD의 `🔒 건드리지 말 것` 목록으로 보호. 이후 변경이 훼손하면 critic이 차단.
- 이전 버전 보존(`dist/v1/` …) — 롤백 가능.

## 6. 구축 순서
| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| P0 | 레포 뼈대, GAME_CONTRACT, FUN_ENGINE | 문서가 §2와 일치 |
| P1 | kit + QA L1·L2 + bundle | kit 샘플 게임이 단일 HTML로 L1·L2 통과 |
| P2 | gen_image + CC0 사운드 라이브러리 | manifest → 이미지·사운드 산출 |
| P3 | 에이전트 7종 + `/make-game` | 아이디어 1개 → 무인으로 HTML 산출 (첫 실전) |
| P4 | QA L3·L4 + `/game-feedback` | 피드백 1회 → v2, 게이트 통과 |
| P5 | "알아서 3개" 병렬 | 입력 없이 3개 산출 |

## 7. 리스크
- **low quality 이미지가 L4를 못 넘을 수 있다** → 히어로 에셋만 퀄리티 상향 옵션.
- **봇이 재미를 대신하지 못한다** → L3는 구조적 실패 탐지용으로만 쓰고, 재미 판정은 사람 피드백.
- **Phaser 인라인으로 번들이 커진다**(~1MB) → 10MB 예산 안. 이미지는 WebP 변환으로 절감.
- **CC0 사운드의 결이 게임마다 비슷해질 수 있다** → 프로덕션 전환 시 생성형으로 교체.
