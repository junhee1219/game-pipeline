# GAME CONTRACT — 모든 게임의 합격 기준

> 하한선은 **바닥**이지 목표가 아니다. 모든 단계는 가능한 최고 품질을 겨냥한다. 비용·시간과 품질이 부딪히면 품질 쪽으로 기운다.
> 품질 기준점: 앵그리버드 · 로얄매치 · 유튜브 광고 캐주얼 게임.

각 항목의 `[L1]`~`[L4]`는 QA 게이트 중 어느 층이 검사하는지를 뜻한다.

## A. 결과물은 HTML
- A1 `games/<id>/dist/index.html` **단일 파일**. 엔진·코드·이미지·사운드·폰트 전부 인라인. `[L1]`
- A2 `file://` 더블클릭으로 실행. 외부 네트워크 요청 0. `[L1]`
- A3 크기 ≤ 10MB. `[L1]`

## B. 복잡하지 않고 쉽게
- B1 엄지 하나, 동사 하나(탭 | 드래그 | 스와이프 중 하나). 멀티터치 금지.
- B2 설명 텍스트 없이 3초 안에 할 일이 자명. 첫 판에만 손가락 힌트 애니메이션. `[L4 블라인드]`
- B2a 블라인드에서 반복 확인된 함정(첫 화면): ① **목표 한 줄**("동물을 울타리로 둘러싸서 가두기!")을 첫 판에만 화면에 띄운다 — 행동 힌트만으론 목표가 안 읽힌다. ② 예고 숫자는 조건형으로 쓴다("닫으면 +12" — "×3 +12"만 쓰면 이미 얻은 점수로 읽힌다). ③ 카운터에는 단위를 쓴다("울타리 3개 뒤", "3번 뒤" ✗). ④ 진행 바에는 무엇을 채우는지 짧은 라벨. ⑤ 손가락 힌트는 누를 대상을 가리지 않게(아래에서 올라오며 누르기 — `Kit.ui.fingerHint(..., {from:'below'})`). ⑥ 첫 판에 쓸 일 없는 재화·칸은 흐리게. ⑦ **첫 화면 글은 최대 2개**(목표 한 줄 + 손 라벨 한 줄) — 규칙 설명 카드를 늘리면 오히려 점수가 떨어진다(starhook 3줄 카드 추가 후 행동 80→65%). 세부 규칙은 처음 일어나는 순간의 피드백(floatText)으로 가르친다. ⑧ 문구의 명사는 화면 그림과 일치(그림이 반딧불이면 '별'이라 쓰지 않는다). ⑨ 색이 규칙이면 색 차이가 테두리가 아니라 덩어리로 보이게. ⑩ 블라인드는 **정지 화면**이다 — 손의 좌우 흔들림 같은 움직임은 안 찍힌다. 조작 방향(조준 범위·드래그 방향)은 정지 프레임에도 보이게 그린다(부채꼴 고스트, ◀▶ 표식). 흐리게 남긴 UI는 오히려 질문을 부르니 첫 판에 안 쓰면 숨긴다. `[L4 블라인드]`
- B2b **자동 전투·결정형 입력 게임의 첫 화면** (모닥불 v4에서 40% → 55% → 90%로 검증): ① 첫 탭 없이 바로 시작하고, 정지 화면에서도 주인공이 이미 싸우는 중이어야 한다. ② 손 시연은 *주인공 발밑*에서 출발해 *다음 위협이 오는 쪽*으로 끈다. 지금 위협과 반대 방향이면 헷갈린다. ③ 첫 화면 고리·표식은 '지금 위치'와 '도착' 두 개만 둔다. ④ 첫 7초는 보상 연출(동전·대박)을 숨겨 시선을 분산하지 않는다. `[L4 블라인드]`
- B3 한 판 1–3분(중앙값). `[L3]`
- B4 기본 시간제한·카운트다운·방치 패널티 없음(판 전체를 재는 타이머를 말한다 — 디펜스·액션의 실시간 진행은 해당 없음, FUN_ENGINE §3.4). 시간 압박이 꼭 필요하면 선택 모드로만.
- B5 변형기·선택지는 첫 문턱 이후에만 등장. 텍스트는 아이콘 + 8자 이내.

## C. 완성도
- C0 **크기 = 재미** (운영자 피드백 2026-10-09: "전반적으로 에셋들이 너무 작아서 재밌는 느낌이 안 나"). 논리 폭 1080 기준:
  - 플레이어가 누르거나 노리는 **주 오브젝트 ≥ 150px**(화면 폭의 ~14%), 주인공·보스 ≥ 240px(~22%). 큰 걸 적게 > 작은 걸 많이.
  - **플레이 영역 ≥ 화면 높이의 65%**. HUD·간판·선반 장식이 플레이 영역을 깎으면 HUD를 줄인다.
  - 격자 게임은 스프라이트가 칸보다 **1.15–1.4배 커서 칸 밖으로 살짝 넘치게**(로얄매치·Kingshot처럼 '꽉 찬' 느낌). 칸이 작아지면 판 크기를 줄이거나 카메라를 당기고 스크롤한다.
  - 판 크기·오브젝트 수를 바꾸면 sim을 다시 돌린다(크기 변경도 밸런스 변경이다). `[L4 비전]` 스크린샷에서 주 오브젝트 bbox를 재서 기준 미달이면 실패.
- C1 화면: 로딩 → 타이틀 → 플레이 → 일시정지 → 결과(점수·최고기록·다시하기). 전부 kit 표준 화면 사용 가능. `[L1]`
- C2 진행 자동 저장 + 새로고침 후 이어하기. 음소거 상태 저장. `[L1]`
- C3 아트: 스타일 앵커 레퍼런스로 통일된 스프라이트. **도형·이모지·플레이스홀더 게임 오브젝트 0.** (파티클의 부드러운 점·별은 허용) `[L4]`
- C4 연출 **5종 이상 발동**(목표는 게임이 허락하는 만큼 풍부하게): kit `juice.*` — shake, pop, squash, floatText, burst, ring, comboPop, flash, bounceIn, hitStop, confetti. `[L2]`
- C5 피크 연출: 문턱 돌파(새 티어 첫 등장)와 신기록에 평소보다 한 단계 큰 전용 연출. `[L2]`
- C6 사운드: BGM ≥ 2곡(로비·플레이), SFX ≥ 10종 사용, 반복 SFX는 피치 변주. 항상 음소거 가능. `[L2]`
- C7 입력 반응은 같은 프레임(즉시 시각/청각 반응), 성공 연출 시작 ≤ 200ms.
- C8 390×844 + CPU 4배 스로틀에서 평균 ≥ 55fps. 콘솔 에러 0. `[L1]`
- C9 UI 주요 버튼은 화면 하단 엄지 영역, 터치 타깃 ≥ 44pt. `[L4]`

## D. 재미 (근거: `FUN_ENGINE.md`)
- D1 이름 붙은 문턱 사다리(≥ 6칸), 숫자를 가려도 서열이 보인다. 다음 칸 실루엣 노출.
- D2 0단계 관문: 변형기 없이도 판마다 "다른 수를 둘 이유"가 있다.
- D3 긴장은 접전과 출렁이는 리듬으로. 벽(통과율 급락 구간) 없음. `[L3]`
- D4 정직한 니어미스만. 결과 조작·가짜 니어미스·숨은 난이도 조절 금지. `[L3 코드 검사]`
- D5 실패 원인이 화면에 보인다.
- D6 4겹 중 시간·일 겹의 골격이 GDD에 있다(이번 빌드에 다 구현 안 해도 됨).
- D7 첫 문턱은 탐욕 봇 기준 60초 안에 ≥ 90% 도달. 최고 티어는 도달 가능하되 드묾. `[L3]`

- D8 **콘텐츠 깊이**(FUN_ENGINE §0.5): 도구 ≥3 · 행동이 다른 대상 ≥4 · 사건 ≥2 · 판마다 변주 ≥1, 해금 일정과 상성표가 GDD에 있고 구현돼 있다. 입력 동사는 여전히 하나. `[L3·크리틱]`

- D9 **가속**: 입력 1회당 출력 사건(타격·합체·수집·연쇄) 수가 판 후반에 초반의 2배 이상(목표 3배). 판 끝 20%(자원 소진·마무리)는 빼고, 초반 1/3 대 이후 가장 출력이 큰 1/3 창을 비교한다(판 어딘가에서 내 출력이 확 커지는가). 적이 빨라지는 게 아니라 내 출력이 커져야 한다. 실시간·장기 게임은 manifest `qa: { botSeconds: 120, botMoveRate: 1, presetSave: {<튜토리얼 완료 키>: 값} }`로 QA 봇을 판 흐름에 맞춘다(presetSave는 첫 화면 촬영 뒤 적용돼 튜토리얼이 아닌 실제 판을 돌린다). `[L2]`
- D10 **죽은 시간 < 5%**: 연출·낙하·정산으로 입력을 못 받는 구간은 `Kit.busy`로 계측하고 판 시간의 5% 미만. 유일한 수는 자동 실행. `[L2]`
- D11 **타격 인과**: 피해·파괴·점수는 원인 동작이 닿는 프레임에 `juice.impact`로 들어간다('근처라서 맞는' 구조 금지). `[L2]`

## E. 테스트 인터페이스 (QA가 쓴다)
- E1 게임은 `Kit.test.register({...})`로 `state()`, `moves()`, `act(move)`, `isOver()`, `score()`, `tier()`를 노출한다. 랜덤 수로는 진행이 안 되는 전략 게임은 **`botMove()`**(지금 둘 좋은 수 하나, 둘 수 없으면 null)도 노출한다 — QA 러너가 75% 확률로 쓴다.
- E2 `act(move)`는 실제 입력과 같은 경로(연출·사운드 포함)를 탄다.
- E3 `Kit.rng`(시드 가능)만 쓴다. `Math.random` 직접 사용 금지(파티클 등 순수 연출 제외).

## F. 보상(포인트) 연동 대비 (설계에만 반영)
- 판당 예고 포인트 금지 · 하루 상한 · 포인트 뽑기 금지 · 스트릭은 복구 가능 · 니어미스 직후 이어하기 판매 금지 · 늦은 밤 "한 판 더" 알림 금지.
